1. Planning principles

  1. Order by dependency, not just severity. Tests and CI gates come before refactors; legal and merchant prerequisites come before real money.
  2. Every task closes a finding or a requirement. Task IDs reference audit finding IDs (F-nn) or requirement IDs (FR-nn, NFR-…).
  3. Definition of done (applies to every task): code with an integration test, CI green (tests, vulnerability gate, drift check, migrations on SQL Server), audit entries for staff actions, docs updated, finding status updated in docs/audits/findings-register.json.
  4. Estimates are preliminary (one developer familiar with ASP.NET Core). The main uncertainties are external: PayFast onboarding, legal review and Azure access.
